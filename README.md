# TourFirm

TourFirm — информационная система турфирмы. Проект предназначен для автоматизации
основных процессов работы сети туристических офисов: приёма заявок на формирование
туров, подбора и согласования маршрутов, ведения истории туров клиентов.

Приложение включает настольный клиент (WPF) для клиентов и работников турфирмы,
серверную часть (ASP.NET Core Web API) и локальную базу данных SQLite.

## Возможности

В проекте реализованы следующие основные возможности:

**Для клиента:**
* регистрация и вход в систему
* создание заявки на формирование тура
* просмотр статуса заявки
* принятие или отклонение предложенных туров
* просмотр туров (предстоящих, активных, прошедших)

**Для работника турфирмы:**
* вход по рабочему месту (офис + устройство)
* просмотр активных заявок
* отправка клиенту нескольких вариантов туров с сопроводительным текстом
* добавление тура клиенту при очном обращении
* просмотр истории туров клиента

## Архитектура

Приложение построено с использованием многослойной архитектуры.
Пользовательский интерфейс не обращается к базе данных напрямую — только через API.

```text
Пользователь
     │
     ▼
Настольный клиент WPF
     │
     ▼
HTTP / JSON
     │
     ▼
REST API (ASP.NET Core)
     │
     ▼
Слой доступа к данным (EF Core)
     │
     ▼
База данных SQLite
```

Такое разделение позволяет независимо развивать клиент, сервер и базу данных,
а также подключать в будущем веб-версию интерфейса без переписывания бизнес-логики.

### Основные компоненты

#### `TourFirm.Data`

Содержит модели предметной области (Client, Employee, TourRequest, TourProposal, Tour)
и контекст `AppDbContext` для работы с SQLite через Entity Framework Core.

#### `TourFirm.Api`

Реализует REST API. Принимает HTTP-запросы, выполняет бизнес-логику, обращается к БД,
возвращает JSON. Документация доступна через Swagger.

#### `TourFirm.Desktop`

Настольный клиент на WPF. Содержит окна для клиента и работника турфирмы,
а также `ApiClient` — единую точку HTTP-запросов к API.

## Требования

Для сборки и запуска проекта необходимо установить:

* .NET SDK 8.0 или выше
* Visual Studio 2022 (Community) с workload'ами **ASP.NET and web development**
  и **.NET desktop development**
* Git

Опционально для работы с миграциями:

```bash
dotnet tool install --global dotnet-ef
```

## Установка

### 1. Клонирование репозитория

```bash
git clone https://github.com/username/TourFirm.git
cd TourFirm
```

### 2. Восстановление зависимостей

```bash
dotnet restore
```

### 3. Создание базы данных

```bash
dotnet ef database update --project src/TourFirm.Data --startup-project src/TourFirm.Api
```

Будет создан файл `tourfirm.db` рядом с проектом API.

## Запуск приложения

В Visual Studio:

1. Правой кнопкой по решению → **Configure Startup Projects**.
2. Выбрать **Multiple startup projects**.
3. У `TourFirm.Api` и `TourFirm.Desktop` выставить действие **Start**.
4. Нажать **F5**.

Будут запущены два процесса: API-сервер и клиентское приложение WPF.
Окно браузера откроется на странице Swagger: `https://localhost:{port}/swagger`.

Через терминал (в двух окнах):

```bash
dotnet run --project src/TourFirm.Api
```

```bash
dotnet run --project src/TourFirm.Desktop
```

## Разработка

Исходный код проекта располагается в каталоге `src/`.
При разработке рекомендуется соблюдать следующую организацию кода:

* модели предметной области размещать в `TourFirm.Data/Entities`;
* работу с базой данных — в `TourFirm.Data`;
* HTTP-контроллеры и бизнес-логику — в `TourFirm.Api/Controllers`;
* код интерфейса — в `TourFirm.Desktop`;
* обращения к API — через единый `ApiClient`.

### Работа с Git

Проект использует модель ветвления **feature branch workflow**:
основная ветка `main` всегда содержит стабильную версию, новые функции
разрабатываются в отдельных ветках `feature/*` и вливаются через Pull Request.

Типичный цикл:

```bash
git switch -c feature/название-задачи
# ... изменения ...
git add .
git commit -m "Краткое описание"
git push -u origin feature/название-задачи
```
